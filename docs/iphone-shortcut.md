# iPhoneショートカットの設定手順

撮影した書籍表紙を `POST /v2/books` へ送信し、Notion登録の成功・失敗をiPhone上で表示する
ショートカットを作成します。APIサーバーは起動済みであり、iPhoneからHTTPSで到達できることを
前提とします。

## 事前準備

1. APIサーバーに `BOOK_REGISTER_API_TOKEN` を設定して起動します。トークンは32〜512文字の
   ASCII文字で、使用できる文字は英数字と `.`、`_`、`~`、`+`、`/`、`=`、`-` です。次のコマンドで
   生成できます。

   ```bash
   export BOOK_REGISTER_API_TOKEN="$(python -c 'import secrets; print(secrets.token_urlsafe(32))')"
   ```
2. APIの公開URLを用意します。インターネット越しに使う場合は、TLS終端を行うリバースプロキシ
   配下の `https://` URLを使用します。
3. ショートカットを新規作成し、名称を「本をNotionに登録」などにします。

トークンを含むショートカットは共有しないでください。共有する場合は、共有前に
`Authorization` ヘッダーの値を削除し、受け取る人が自身のトークンを設定できるようにします。

## アクションを並べる

ショートカットアプリで、次の順番にアクションを追加します。アクション名はiOSの表示言語や
バージョンにより多少異なる場合があります。

1. **「写真を撮る」**を追加します。カメラは背面、プレビューは必要に応じてオンにします。
2. **「画像を変換」**を追加し、出力形式を `JPEG` に設定します。iPhoneがHEIC/HEIF形式で
   撮影する設定でも、APIに対応するJPEGデータとして送信するために必要です。
3. **「Base64でエンコード」**を追加し、入力に前段のJPEG画像を指定します。詳細を表示して
   **「改行」**を `なし` に設定します。出力は次の「辞書」で `image` の値に使います。
   `data:image/jpeg;base64,` のような接頭辞は付けません。
4. **「辞書」**を追加し、次のキーを設定します。

   | キー | 値 | 種類 |
   | --- | --- | --- |
   | `image` | Base64でエンコードの結果 | テキスト |
   | `mime_type` | `image/jpeg` | テキスト |
   | `genre` | 例: `技術書` | テキスト（任意） |

   撮影画像がPNGなら `mime_type` を `image/png` に変更します。`title` と `author` はISBN検索が
   失敗したときの補助情報で、使う場合は必ず両方を追加します。

5. **「URLの内容を取得」**を追加します。詳細を表示して、**「エラー時も続ける」**をオンにします。
   このガイドの個別エラー表示・再試行分岐は、この設定を利用できるiOSを前提とします。これにより、
   HTTP 400/401/413/415/422/502などの非2xx応答でも本文の `message` と `error` を後続で
   扱えます。接続上限によるHTTP 503だけは `{"error":"Server is busy."}` という特別形式で、
   `message` や `ok` は含みません。これは手順6で先に分岐します。以下のように設定します。

   | 項目 | 設定 |
   | --- | --- |
   | URL | `https://<公開URL>/v2/books` |
   | メソッド | `POST` |
   | リクエスト本文 | `JSON` |
   | JSON | 前段の「辞書」 |
   | ヘッダー | `Authorization: Bearer <BOOK_REGISTER_API_TOKEN>` |
   | ヘッダー | `Content-Type: application/json` |

   この設定が表示されないiOSでは、非2xx応答でショートカットが停止するため、後続の
   `message`・`error.retryable` 分岐は利用できません。個別の失敗理由を表示するこの手順を使うには、
   この設定を利用できるiOSで作成・実行してください。

6. レスポンスから最初にトップレベルの `error` を取得します。値が `Server is busy.` の場合は
   接続上限によるHTTP 503です。**「待機」**で数秒待ってからショートカットを終了するか、
   同じ送信処理を一度だけ再実行する分岐にします。この503応答には `ok` がありません。
   本文を受け取れない環境では、前段の代替処理で待機後の手動再実行を案内してください。
7. `error` が `Server is busy.` 以外の場合は、`error` の有無にかかわらず**「辞書の値を取得」**で
   レスポンスの `ok` を取り出し、**「もし」**で分岐します。
   `ok` が真なら `message` を**「結果を表示」**します。さらに `result` から `page_url` を
   取り出して**「URLを開く」**を追加すれば、作成・検出したNotionページを開けます。
8. `ok` が偽なら、レスポンスの `message` を**「結果を表示」**します。`error.retryable` が
   真の場合だけ「少し待って再実行してください」と案内する分岐を追加できます。

## レスポンスの扱い

正常終了時はHTTP 201（新規作成）またはHTTP 200（重複を検出）のJSONが返ります。
どちらも `ok: true` で、`result.created` が新規作成かどうかを表します。

```json
{
  "ok": true,
  "message": "書籍をNotionに登録しました。",
  "result": {
    "page_url": "https://www.notion.so/...",
    "created": true
  }
}
```

入力不備、ISBN未検出、書誌なし、外部サービス障害などでは `ok: false` と `message` が返ります。
ショートカット側では詳細な例外文ではなく、`message` と `error.code` を表示・分岐に使用します。

接続上限によるHTTP 503だけは、サーバーがURLを判別する前に返すため `ok` を持たない
`{"error":"Server is busy."}` です。「URLの内容を取得」でHTTPエラーとして扱われる場合も
あるため、503では短時間待ってから再実行するようにしてください。

## 動作確認

1. 表紙のISBNバーコードが読めるように撮影して実行します。
2. 初回は「書籍をNotionに登録しました。」と表示され、Notionページが開くことを確認します。
3. 同じ本をもう一度実行し、成功のまま `created: false` 相当の重複メッセージになることを確認します。
4. ISBNがない画像では、失敗メッセージが表示され、Notionに新規ページが作られないことを確認します。
